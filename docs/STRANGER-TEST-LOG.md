# Stranger test log: g90 Tactics Arena (turn-based arena)
Tester: fresh AI, 2026-10-31. Every entry: what happened, then a suggested fix.

1. 2026-10-31 GENERIC-KIT s8 says "`python3 new.py ...` or manual scaffold" but there is no turn-based starter and `--starter` has no such genre. The non-starter form of new.py (`new.py g90 "Title" LA LB "keys" "mashup"`) is documented nowhere in the docs (only in its own docstring) and it OVERWRITES `games/g90.js` with a template. I had to back up my file, run it for the games.json entry, then restore. Fix: document the 6-argument form in section 1, and say it writes games/gNN.js (or add `--register-only`).
2. 2026-10-31 Section 8 / Section 2 / header comment of engine.js: "Uses engine.js for grid/path/fx" - but `ENG.path` is a polyline (distance -> x,y), not grid pathfinding, and ENG.grid has only get/set/solid, no flood fill or BFS. The real grid helper `bfs(w,h,pass,sx,sy,goal)` lives in gamekit.js and is in no doc (I found it by reading gamekit.js, outside the allowed list; also `dirInp`, `mkEdge`/`S.edge`, `popup`, `burst`, `hintS`, `finish`, `rint`, `pick`). Fix: add a "kit helpers" table (bfs, dirInp, S.edge, popup, burst, hintS, finish, hurtS, bar) to KIT-API.md and say checklist line 4 is satisfied by ENG.grid (board) + bfs + ENG.path (slide) + ENG.fx.
3. 2026-10-31 Section 8 line 4 is ambiguous: "no hand-rolled collision". A tile game has no collision; distance checks (manhattan range) and reachability are rules. Fix: state that range/adjacency tests on a tile grid are allowed, only AABB/circle overlap and spawn/aging loops must go through engine.js.
4. 2026-10-31 FEEL-SHEETS turn-based row: "40% hit-chance spread, hp 8-12, attack range 1-2, move 3". Unclear: spread of what (hit chance range from 90% to 50%?), damage not given, no AI aggression value, no unit kinds, no turn limit, no way to get a bot win. I had to invent: hit 0.9 at range 1 minus 0.2 per tile (min 0.3), dmg 3 then 2, knight hp 12 / archer hp 8, aggression 0.5, manhattan range. Fix: give a full start sheet (kinds, dmg, hit formula, AI aggro, turn cap).
5. 2026-10-31 Biggest gap: symmetric armies with dice make the bot win about 50% (measured: 4/8, 3/8, 5/8, 10/24 across variants), so "bot wins 8/8" (line 2) is not reachable by following the sheet. What worked: bot gets exposure-aware tile scoring (botCaution 0.6), focus-fire weight and acts best-attack-first; AI loses kill bonus (aiKill 0) and enemy hp x0.7 (foeHp, knight 8 / archer 6). Result 40/40 seeds. Fix: add to the sheet "turn-based needs a handicapped AI (hp x0.7 or equal army with a dumb target rule); symmetric dice games are a coin flip", plus the bot recipe above.
6. 2026-10-31 `check.sh gNN 90` outputs a game that ends at about 20-45 s, so the seedcheck 25 s / 60 s samples are often taken after game over (the info is then the final state, still seed-different, but the frame hash is skipped). Docs say nothing about games shorter than 60 s. Fix: say that a short game is fine (final state is compared) or give a minimum length.
7. 2026-10-31 Art tier cannot be built from the sandbox/doc recipe: `python3 build.py g90 --art` crashes with FileNotFoundError art/atlas.json, and the documented fix `node art/build-art.cjs` fails (ENOENT art/hero_rig.svg, the SVG sources are not in the kit). The traceback is a raw Python error, not the friendly "BUILD FAILED" message the docs promise (that only fires for games with `// NEEDS: art`). Workaround I used and it is a guess: `echo '{}' > art/atlas.json` (empty atlas; g90 uses no RIG sprites so GLPOST alone is exercised). Fix: ship a stub atlas.json or make build.py write `{}` when missing and the game has no NEEDS: art; document that --art only needs atlas.json for RIG games. Also section 4 says "the third tier is free" - true only once atlas.json exists.
8. 2026-10-31 Doc says output pages are named gNN.art.html; tiers.cjs and baseline.cjs want the argument `g90.art` (no .html). Section 4 never states the hd page is `gNN.hd.html`. Fix: one line "arguments are page basenames: g90 g90.hd g90.art".
9. 2026-10-31 `./check.sh gNN 90` must be run from kit/cabinet after `source env.sh`; the doc shows it only in section 1 as part of `cd kit/cabinet && source env.sh`, section 8 gives it bare. check.sh itself does the cd, but playwright needs env.sh first. Fix: repeat the two-line prefix in section 8.
10. 2026-10-31 The HUD lint is a text awk: any hud() containing the substrings `rect(`, `fillCircle(`, `spr(`, `ART.` fails, even inside strings. Not documented beyond "check.sh lints this". Fix: say it is substring based.
11. 2026-10-31 Bot contract: docs say bot fills an `NI()` input, but not that for a cursor game the bot must emit real key edges. `S.edge(inp,'a')` is per-frame state, so it must be called every step (not inside a short-circuited `&&` chain), and the bot's `a` must toggle (s3 uses `(S.T*30|0)&1`). I copied s3's pattern; a stranger copying nothing would hit this. Fix: add two lines to section 3.
12. 2026-10-31 During attract/title mode `bot()` runs and `finish()` returns 'reset' (S.att); the step must return finish's value. Documented only in a code comment of gamekit.js. Fix: mention in section 3 item 3.
13. 2026-10-31 info() key `mode` is added by the shell (info() merges `mode,result,hi`); a game naming its own field `mode` would collide with tiers.cjs's lvl-game detection (it checks `i.lvl`). I avoided it (used `ph`). Fix: document reserved info keys: mode, result, hi, score, t.
14. 2026-10-31 Section 8 line 6 says "no value had to be guessed from a finished game": satisfied, but values for the turn-based genre were guessed from the sheet (see 4, 5). The wording should be "from any source other than the sheet" to be testable.
15. 2026-10-31 FEEL-SHEETS says hp 8-12 and the checklist TUNE needs "AI aggression"; the kit has no AI helper at all (nothing in engine.js for enemy decision making), so the whole AI plus the bot plan is hand-written (about 15 lines, shared plan90). Fix: offer a tiny `plan` pattern in the docs: one scorer used by both AI and bot.
